基于 Open-Vocabulary 的道路设施提取

本文档用于整理“基于 Open-Vocabulary 的道路设施提取”论文写作思路、实验设计和评估体系。研究目标是利用图像理解模型与彩色点云数据，实现道路设施要素的开放词汇提取、实例分割与属性估计。

论文写作框架

研究现状

Open-Vocabulary 方法研究现状

围绕开放词汇视觉理解与道路设施提取，重点梳理以下两类方法：

  • 图像开放词汇方法：分析 Grounding DINO、T-Rex2、SAM、Grounded SAM 等方法在开放类别检测、分割和提示词驱动识别中的能力。
  • 点云开放词汇方法：分析 OpenIns3D 等 3D 开放词汇实例分割方法在彩色点云、室外道路场景和小目标设施上的适用性。

需要重点讨论的问题：

  • 现有 2D 开放词汇模型是否能稳定识别道路设施中的细粒度类别。
  • 现有 3D 开放词汇模型是否适合大规模室外道路点云。
  • 图像知识如何迁移到彩色点云要素提取任务中。
  • 分割结果与道路设施属性估计之间如何建立关联。

点云与图像语义/实例分割研究现状

围绕道路设施提取任务，需要补充传统监督式语义分割与实例分割方法的研究现状，作为 Open-Vocabulary 方法的对照基础。

  • 图像语义/实例分割方法：分析 Mask R-CNN、Mask2Former、Segment Anything 等方法在道路场景图像中的目标分割能力。
  • 点云语义分割方法：分析 RandLA-Net、KPConv、MinkowskiNet 等方法在室外点云语义理解中的应用。
  • 点云实例分割方法：分析 ISBNet、SPFormer 等方法在道路设施实例分割和跨场景泛化中的表现。

需要重点讨论的问题：

  • 监督式分割方法对训练数据和类别定义的依赖。
  • 图像分割方法在遮挡、小目标和远距离目标上的限制。
  • 点云分割方法在稀疏点云、杆状物和树木等复杂结构上的表现。
  • 传统分割方法与 Open-Vocabulary 方法在类别扩展能力上的差异。

数据集研究现状

数据集综述重点关注道路设施类别是否覆盖完整，尤其是俯视与侧视要素是否同时具备。

  • 数据模态：图像、点云、彩色点云、融合数据。
  • 采集视角：俯视、正视、侧视、多视角。
  • 类别覆盖：车道线、交通标志、杆状物、道路附属设施、绿化设施、公共服务设施等。
  • 标注粒度：语义分割、实例分割、检测框、属性标签。
  • 道路场景复杂度：城市道路、园区道路、交叉口、居住区道路等。

论文贡献

  1. 提出基于图像知识的彩色点云 Open-Vocabulary 道路设施提取方法。结合 2D 开放词汇图像分割结果和彩色点云空间结构，实现道路设施实例提取与属性估计。方法不依赖与点云严格同步或完美配准的真实 2D 图像，因此适用于仅有点云、缺少对应图像或图像存储成本较高的道路场景数据。
  2. 构建并发布 RS30 自采道路设施数据集。数据覆盖蔡家浜路、财聚路、荣欣路三个真实道路场景，包含俯视道路要素和正视道路设施要素。

方法设计动机：

  • LiDAR 点云经常缺少严格对应的 2D 图像，例如 Semantic3D、Toronto3D、Paris-CARLA-3D。
  • Photogrammetry 点云很多时候没有可直接使用的深度图，例如 Campus3D、STPLS3D、SensatUrban。
  • Simulation 或 CAD 模型转点云时可能没有配套真实 2D 图像，例如 SynthCity。
  • 多传感器配准后的融合点云模型难以找到完美对应的 2D 图像。
  • 2D 图像存储和处理成本较高。例如在 ScanNetv2 中，一个 3D 点云或 mesh 可能只有数 MB，但对应 RGB-D 图像可能达到 GB 级。

实验设计

实验目的

  • 与现有 2D Open-Vocabulary 方法相比，验证本文方法是否能获得更稳定的 3D 道路设施实例。
  • 与现有 3D Open-Vocabulary 方法相比，验证本文方法是否更适合道路场景中的细粒度设施提取。
  • 将 ISBNet、SPFormer 作为纯点云闭集监督实例分割基线，验证纯点云实例分割是否依赖训练场景。
  • 分析纯点云实例分割模型迁移到新道路场景后性能下降的程度。
  • 验证图像知识驱动方法是否具有更好的跨场景泛化性。
  • 验证 Open-Vocabulary 方法在新增类别时是否比闭集点云模型更灵活。

3D Open-Vocabulary 实验分析：OpenIns3D

为验证本文方法在室外道路设施提取任务中的有效性，选取 OpenIns3D 作为现有 3D Open-Vocabulary 实例分割方法进行对比。在统一的测试场景、类别词表和实例真值下，采用实例 IoU > 0.5 作为正确匹配条件，并统计 Precision、Recall 和 F1-Score。由于本文关注的类别与 STPLS3D 等公开数据集并不完全一致，正式实验不直接以公开 AP50 数值替代本文测试结果，而是使用相同真值和匹配规则重新评价。

定量趋势：OpenIns3D 在自采 MLS 道路点云上的整体性能预计较低，尤其在电线杆、路灯杆、交通标志、果壳箱、消防栓和电箱等细长或小尺度目标上表现为较低的 Recall，部分类别可能无法形成有效预测实例。其公开 STPLS3D 结果也表现出明显的类别差异：建筑、车辆等大型目标的 AP50 相对较高，而灯杆、街道标牌等小型道路设施的 AP50 很低。该趋势与本文测试中观察到的小目标漏检现象一致。正式论文中可报告总体及共有类别的 Precision、Recall 和 F1-Score，具体数值待实例真值评估完成后填写。

定性现象：OpenIns3D 对建筑、植被、车辆和部分围栏等点数较多、空间范围较大且几何边界明显的目标具有一定提取能力，但对杆状物和小型附属设施容易出现漏检、掩码破碎、过分割或类别匹配失败。即使 ODISE 能够在部分合成视图中识别目标，二维分割结果也可能因为与三维候选掩码的重叠不足而无法完成稳定的类别回传。

原因分析：首先，Mask3D 生成的类别无关候选掩码对目标尺度、点数和点云采集域较为敏感，航空摄影测量点云与车载 MLS 点云在采集视角、点密度、遮挡模式及目标尺度方面存在明显差异。其次，小型设施点数少、结构细长，并常与树木、建筑及街景背景发生遮挡，难以形成完整且稳定的三维候选。最后，Snap 模块采用场景级多视角投影，小目标在合成图像中的像素占比较低，进一步限制了二维识别和二维—三维匹配的效果。

综合来看，OpenIns3D 的结果说明现有“类别无关三维候选生成—合成视图开放词汇识别—二维三维匹配”流程对室外大型目标具有一定适用性，但在 MLS 道路场景中的细长、小尺度设施提取方面仍存在明显局限。本文方法通过图像知识驱动的实例提取、三维融合以及面向道路设施的后处理，提高小型目标和杆状目标的检出能力，并增强跨场景适应性。

定性实验分析

提示词敏感性与 Pipeline 稳定性

该实验的目的不是证明某个 prompt 最优，而是说明 Open-Vocabulary 方法对文本提示存在敏感性，并分析本文 pipeline 如何通过 3D 融合和实例后处理缓解部分不稳定结果。

建议选择电线杆、路灯杆、交通标志、行道树、围栏等典型类别，展示以下提示词设置下的分割结果：

  • 中文类别名与英文类别名。
  • 粗粒度 prompt 与细粒度 prompt。
  • 单类别 prompt 与多类别 prompt。
  • 同义词或近义词 prompt。

结果展示以图片对比为主，可放在定性分析或讨论部分，用于解释不同提示词下的漏检、误检和实例粘连现象。

道路要素提取结果展示

  • 俯视要素实例分割结果：展示车道线、转向箭头、斑马线、井盖、人行道等要素的实例级分割结果。
  • 正视要素实例分割结果：展示电线杆、路灯杆、路牌、交通标志、红绿灯、监控、行道树、围栏等要素的实例级分割结果。

评估体系

实例级评价指标

  • Precision：预测正确的实例数量 / 预测实例总数。
  • Recall：预测正确的实例数量 / 真值实例总数。
  • F1-Score：Precision 与 Recall 的调和平均。

实例匹配规则

  • 当预测实例与真值实例的 IoU > 0.5 时，视为正确匹配。
  • 每个真值实例最多匹配一个预测实例。
  • 每个预测实例最多匹配一个真值实例。

真值获取方案

评估真值统一采用实例分割真值标注，不再使用人工统计作为正式评价依据。

  • 对蔡家浜路、财聚路、荣欣路三个自采场景进行实例分割真值标注。
  • 每个道路设施实例应具有类别标签和实例 ID。
  • 所有主要方法和消融实验均基于同一套实例真值进行评估。
  • 对关键类别和主要对比方法使用 IoU > 0.5 的实例级评价。
